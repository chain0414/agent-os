# Codex ↔ DSH 独立协作插件：第一版设计

日期：2026-10-29。状态：待 Wayne 确认；仅完成接入调查和设计，尚无插件实现或真实互通结果。独立实施规划检查未发现遗留的重要问题；该检查不代表接口兼容性或端到端行为已验证。

## 用户目标与已确认范围

Wayne 希望在当前 Codex / DeepSeek Harness 对话中叫另一方协助，双方都能发起委派和复核。主要流程是：在 DSH 讨论方案 → Codex 交叉复核 → 结果返回原 DSH 对话 → 确认方案 → Codex 编码执行。

产品作为独立插件交付，尽量复用 Agents Anywhere 已有接入经验；安装、运行和基础协作不依赖 AA Server、账号或 Connector。AA 可以作为后续适配目标。

第一版成功标准：从真实 DSH 当前对话发起一次 Codex 方案复核，结果自动回到同一 DSH 对话；用户确认某版方案后，Codex 收到对应版本并执行编码；另验证一次 Codex → DSH 的反向复核。以上均需真实环境验收，模拟结果不替代。

## 推荐路线与替代方案

用户已选择从原生对话调用对方、独立插件并可选接入 AA 的产品路线。

技术方案由 Agent 推荐：本机协作服务 + Codex 插件（Skill / MCP）+ DSH 原生插件。先支持同一台 Mac；跨设备通过以后新增的适配器实现。

- 纯 Skill + CLI：可用于显式调用，但可靠回传、会话绑定和恢复需要脚本服务，难以单靠提示词实现完整体验。
- 本机服务 + 两端插件（推荐）：两端共用任务记录与回传机制，独立安装，较适合当前对话协作。
- AA Server / Connector 中心调度：现有能力多，但引入 AA 运行依赖，不符合默认独立运行的要求，作为可选适配器保留。

建议项目暂名 `codex-dsh-bridge`，本地实现目录 `/Users/wayne/mywork/workspace/codex-dsh-bridge`。名称、TypeScript / Node 技术栈、同机 Mac 优先均为 Agent 的实现建议。本文暂放 AA 仓库便于追溯现有接入；实施时迁入独立项目，不从 AA 源目录运行时导入。GitHub 所有者、可见性与发布暂未指定，本轮不创建远程仓库或发布包。

## 用户如何使用

以下对话均为设计示例，不是真实调用记录。

1. Wayne 在 DSH 说：“把当前方案交给 Codex 交叉 review，重点看并发和迁移风险。”
2. DSH 调用插件，将本次目标、原始约束、方案原文、需要查看的文件和复核重点交给 Codex。绑定来源会话与这次方案版本。
3. Codex 在绑定的协作会话中复核；没有绑定时建立一个专用协作会话，后续复用。复核默认不修改项目文件。回传原文，包括具体问题、证据、严重程度、替代方案及尚未验证的假设。
4. 结果作为可识别的“来自 Codex 的复核结果”进入原 DSH 对话；DSH 对每条意见给出采纳、拒绝或待验证的理由，并提出更新方案。双方一致不代表方案已被证明正确。
5. Wayne 在 DSH 说：“按这版方案让 Codex 开始实现。”插件固定该版方案、工作目录与验收标准，交给同一个 Codex 协作会话继续编码。
6. 编码结果、改动说明、验证证据和未完成事项回到原 DSH 对话。Codex 也能调用相同工具请求 DSH 对方案或改动复核。

默认方案复核结束不自动进入编码；用户已经明确授权编码时，不重复要求确认。上述“用户确认后编码”是对 Wayne 所说“确认好方案”的保守解释，作为设计默认待确认，而不是用户已经明确规定的额外流程。

不新建管理面板；优先通过两端原生对话展示请求、结果和必要状态。不在产品对话中塞入连接日志、协议细节或内部验收说明。

## 会话与任务语义

“当前对话”是调用来源，任务结果必须可回到它。接收端默认使用该协作绑定的持久会话，允许选择已有会话；不任意挑选最近打开的对话。

每个委派包含：任务 ID、类型（咨询 / 方案复核 / 改动复核 / 编码）、来源与目标会话、父任务、工作目录、任务输入版本、交付要求、授权范围与预算。每个任务只有一个执行方；双方均能发起新任务。

方案使用内容摘要标识版本，复核关联准确版本；用户修改方案后，旧复核不能当成新版已通过。编码交接包含确定的完整方案、已解决与未解决的分歧、文件范围和验收条件，不只给对方一段 Agent 摘要。读取差异时固定基线与改动版本。

回传保留模型原文，来源身份由适配器记录，不接受模型文本自行声明身份。摘要与原文分别标识；大结果保留完整本地文件并提供定位，不静默截断关键限定条件。

## 最小组件与接口

- 本机服务：轻量持久存储（优先 SQLite）、任务生命周期、双向会话绑定、结果投递队列、重连恢复和用量记录。
- Codex 插件：Skill 指导何时委派与如何交接；MCP 暴露调用操作；Codex 会话由独立适配器驱动。
- DSH 插件：在当前工具调用上下文中取得可靠 session ID，注册协作工具，接收回传并触发后续轮次。
- 可选 AA 适配器：实现同一运行时接口；核心不依赖 AA API、Python 包、账号或数据库。

建议模型可见操作只保留委派、读取结果 / 等待、补充输入、取消、查询能力。复核与编码通过委派类型区分。MCP 的 `cancel` 只取消此插件创建并拥有的任务；不扩大为任意停止对方会话。

通信先采用本机 socket 或受认证的 loopback 接口；状态文件限制为当前用户访问。凭据不进入任务正文、命令行参数或日志。传递的工作目录是任务上下文，不等同于文件系统权限沙箱；执行限制由各 Runtime 的实际能力落实。

## 执行与回传的关键规则

- 发起后立即得到任务 ID；长任务不能靠一个一直挂起的工具调用维持。允许短等待，超时后仍能查询及接收回传。
- 发起方正在调用并等待目标时，结果通过工具返回；发起方已结束该轮时，使用持久投递队列，在原会话空闲后发起一次结果通知。不以另起用户消息方式重复注入同一结果。
- 被占用的目标会话排队，不抢占、不另开一个 app-server 强行 resume；队列状态可见，用户能取消。会话归档 / 不可达时保留结果，显示重试或重新绑定入口，不静默改投其他会话。
- 请求、执行与投递分别跟踪状态，区分执行完成和已回传。使用幂等标识去重；发送超时且结果不确定时先核查，不盲目重发，不承诺所有底层协议都具备 exactly-once。
- 来自对端的结果不是用户新授权，不自动继续派活。禁止委派链回到仍在等待的祖先任务；需要澄清时以补充信息返回，避免双方互等。自动追问默认不超过两轮，可按任务修改。
- 复核使用接收端实际可用的只读 / 受限能力；不能保证不修改项目时拒绝以“只读复核”执行并说明限制。不能只靠提示词宣称只读。
- 编码任务不继承批准部署、合并、发布或答复权限审批的权力；原生审批留在原 Runtime。需要用户处理时回传准确的阻塞与入口。

## 上下文与 token

第一次交接包含足够独立理解的需求、方案和证据；后续复用接收端会话，只发送变化。按需读取文件和完整记录，避免每轮复制全部聊天；接收方能请求缺失背景。

第一版记录双方 Runtime 可提供的真实用量，缺失则标未知，估算单独标注；优先控制交接输入、输出长度、自动往返次数、执行时间与并发。原生支持预算时才传入真实 token 限制。插件不声称账号额度可以转移，也不声称仅凭结束后的用量通知能严格控制执行中 token。

## 已有证据与复用边界

本节为源码 / 官方文档事实；上文是建议设计。

- AA `dsh-bridge-next/src/host/dsh-runtime/router.ts` 已有创建与启动会话、开始轮次、中断、快照 / 状态读取等路由；`native.ts` 负责原生调用。复用其领域映射与行为经验，需要剥离 AA 的 ID、日志、同步与账号关系。
- `dsh-runtime/connection.ts` 使用 Connector 发布的 rendezvous 注册 bridge，并含 AA Sync / Logs 调用。因此不能把整个现有 DSH 插件包装一下就称为独立运行。
- AA `connector/connector/runtimes/codex/sdk/runtime_client.py` 定义 app-server 客户端接口；`codex/ipc/control.py` 对桌面 owner 使用 `thread-follower-*` 写操作。接入已有桌面对话需要 owner 路由，不能把 app-server 的恢复存档接口当成加入任意活跃窗口。
- [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server) 描述 thread / turn 生命周期与 `thread/tokenUsage/updated`；不据此推断任意桌面窗口都能直接控制。
- [官方插件 Skills 文档](https://developers.openai.com/plugins/concepts/skills) 区分 Skill 工作流与 MCP 可执行动作。

复用源码前检查许可证及分发条件；适配器不得从 AA checkout 运行时导入。优先复用已验证的小模块，避免复制整套 Connector 形成两份难以同步的实现。

## 实施顺序与验收

1. 接入探针：确认已安装 DSH 版本的工具注册、当前 session 上下文及回传触发；确认 Codex 的创建协作会话、桌面 owner 路由与事件能力。先用无敏感信息的固定请求，只验证传输，不能把它当成真实方案复核验收。记录支持的版本。
2. 纵向闭环：真实当前 DSH 发起 Codex 复核，完整结果回到原会话，覆盖短等待与离开等待后的异步回传。可在原生 Codex 客户端查看对应协作会话。
3. 方案交接：确认具体版本后 Codex 执行小规模真实代码任务，返回实际改动与验证结果；与仓库原内容比较，证明执行的是确认版本。
4. 双向与恢复：Codex → DSH 复核；覆盖重启、断线、目标忙、回传失败、重复事件、取消以及权限阻塞。
5. 独立安装：在无 AA Server、无 Connector 运行时验证以上核心能力；再考虑 AA 适配。

本机服务用可控假适配器验证路由、幂等、状态恢复、版本关联、循环与取消。真实端到端记录另列，明确真实输入、模型原文、人工判断与未经验证内容。Headless 测试通过不代表原生回传可用。

若当前 DSH 无法可靠回传到原对话，或当前 Codex 桌面无法安全加入指定会话，先报告具体版本与阻塞，不退化为让 Wayne 手工复制粘贴后仍宣称目标完成。专用 Codex 协作会话符合默认设计；控制用户任意已有活跃窗口属于额外兼容能力，未通过探针不得承诺。
